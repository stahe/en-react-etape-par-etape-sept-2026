    8. Communicating with the server

    The examples in this chapter query the server JSON [RdvMedecins]: It must be running ([npm run start:dev] in the [rdvmedecins-nestjs-json] folder) on port 8080, at the same time as the [Vite] development server on port 5173.

    8.1. Example 22: An initial request for HTTP

    8.1.1. The development server’s proxy

    The page in this example comes from http://localhost:5173 (the [Vite] development server); API is located at http://localhost:8080. To a browser, these are two different origins (the port is part of the origin). However, for security reasons, a browser does not allow a page to read responses from another origin unless the server explicitly permits it (the mechanism known as CORS). And a request to another origin does not carry cookies (and therefore not the token), unless the code requests it ([credentials: 'include']) ET and the server accepts it, again via CORS.

    Rather than opening the server to other origins, we route requests from API through the development server at [Vite]. This is the proxy declared in the [vite.config.ts] file in the examples (see Example 01):

// 22-fetch/src/App.tsx - a first request HTTP to the server
// -------------------------------------------------------------------------
// The server JSON RdvMedecins must be running (port 8080). It is asked to
// a CAPTCHA: GET /api/captcha -> { "id": "...", "svg": "<svg ...>" }.
//
//    - fetch(url): the browser function that sends a request HTTP.
//      It returns a PROMESSE from the response; reponse.json() a promise
//      for the body, converted from JSON. React does not have its own HTTP client;
//    - the address is RELATIVE (/api/captcha): the request is sent to the
//      page’s server, Vite’s server (port 5173), which forwards it to the
//      JSON server (port 8080) via its proxy (see vite.config.ts);
//    - three statuses to display: in progress, successful, error.
// =========================================================================

import { useEffect, useState } from 'react';

// what GET returns for /api/captcha
interface Captcha {
  id: string;
  svg: string;
}

const styleCaptcha = { display: 'inline-block', border: '1px solid #dee2e6', borderRadius: '0.375rem' };

export default function App() {
  const [captcha, setCaptcha] = useState<Captcha | null>(null);
  const [enCours, setEnCours] = useState(true);
  const [erreur, setErreur] = useState<string | null>(null);
  const [nbRequetes, setNbRequetes] = useState(0);
   // Every click on "Another image" changes this number, which restarts the effect
  const [demande, setDemande] = useState(0);

  useEffect(() => {
     // AbortController: the way to ANNULER a pending request
    const annulation = new AbortController();
    setEnCours(true);
    setErreur(null);
    fetch('/api/captcha', { signal: annulation.signal })
      .then(async (reponse) => {
         // fetch does not return an error response (4xx, 5xx): test passes
        if (!reponse.ok) {
          throw new Error(`le serveur a répondu ${reponse.status} ${reponse.statusText}`);
        }
        const c = (await reponse.json()) as Captcha;
        setCaptcha(c);
        setNbRequetes((n) => n + 1);
        setEnCours(false);
      })
      .catch((e: Error) => {
        if (e.name === 'AbortError') return; // request canceled: nothing to display
        setErreur(e.message);
        setCaptcha(null);
        setEnCours(false);
      });
     // cleans up the ANNULE request if the effect is restarted or if the
     // component disappears before the response. In development, StrictMode
     // executes the effect twice at startup: the first request is
     // canceled (Network tab: “canceled”); only the second one counts.
    return () => annulation.abort();
  }, [demande]);

  return (
    <div className="container py-4" style={{ maxWidth: 640 }}>
      <h1 className="h3 mb-3">Exemple 22 - une première requête HTTP</h1>
      <div className="card p-3">
        {enCours && <p className="text-muted">Chargement...</p>}
        {erreur && (
          <div className="alert alert-danger mb-3">
            Impossible d'obtenir un captcha : {erreur}.<br />
            Le serveur JSON RdvMedecins est-il lancé (port 8080) ?
          </div>
        )}
        {captcha && !enCours && (
          <>
            {/* dangerouslySetInnerHTML: insert a string like HTML */}
            <div className="mb-2"><div style={styleCaptcha} dangerouslySetInnerHTML={{ __html: captcha.svg }} /></div>
            <p className="small text-muted">id : <code>{captcha.id}</code></p>
          </>
        )}
        <button className="btn btn-primary align-self-start" disabled={enCours} onClick={() => setDemande((d) => d + 1)}>
          Autre image
        </button>
        <p className="small text-muted mt-2 mb-0">
          {nbRequetes} requête(s) réussie(s) - ouvrez l'onglet Réseau des outils de développement (F12).
        </p>
      </div>
    </div>
  );
}
    • lines 19–22: what [GET /api/captcha] returns;
    • lines 27–30: three states to display: in progress, successful (the CAPTCHA), error;
    • line 32: a request number: each click on “Another image” increments it, which triggers the effect again;
    • lines 34–61: the request is an effect: it synchronizes the component with the server, upon initial display and then with each new request:
      • line 36: a [AbortController] allows you to cancel a pending request: it changes its [signal] to [fetch];
      • line 39: [fetch(url)] sends a request (GET) and returns a promise for the response. The address is RELATIVE: the request is sent to the page’s server, [Vite], which forwards it to the server JSON;
      • lines 42–44: ATTENTION: [fetch] does not reject PAS if it receives an error response (4xx, 5xx); its promise is rejected only if the AUCUNE response does not arrive (network outage). Therefore, [reponse.ok] is checked (true for a 2xx code);
      • Line 45: [reponse.json()] reads the body and converts it from JSON (another promise). [as Captcha]: We tell [TypeScript] the format of the received data; it cannot verify this;
      • lines 50–55: an error; [AbortError]: the request was canceled; there is nothing to display;
      • Line 60: The ANNULE cleanup checks whether the effect is re-triggered or if the component disappears before a response is received. In development, [<StrictMode>] runs the effect twice at startup: the first request is canceled (the Network tab shows it as “canceled”); only the second one counts;
    • line 77: the image is a snippet of SVG, a string to be inserted like HTML. [{captcha.svg}] would display the text [<svg ...>], escaped. [dangerouslySetInnerHTML] inserts the string as-is: its name warns of the danger. Use QUE only for safe content: this SVG is generated by the NOTRE server. With user input, this would open the door to script injection;
    • Line 81: a new request; the effect is triggered again.

    If the JSON server is down, the [Vite] proxy returns a 500 error: “Unable to obtain a CAPTCHA: the server responded with a 500 Internal Server Error.”

    // =========================================================================
// 23-connection/src/App.tsx - connect to the server RdvMedecins
// -------------------------------------------------------------------------
//    1. On startup: GET /api/auth/moi - are we already logged in?
//       (after a F5, the client has forgotten everything; the server, however, reads the cookie);
//    2. Login: POST /api/auth/login, body JSON { login, password,
//       captchaId, captcha }. If successful, the server sets the cookie
//       httpOnly from the token JWT: our code doesn't recognize it JAMAIS (try
//       document.cookie in the console: it’s not there);
//    3. Protected request: GET /api/medecins. The browser includes the cookie
//       on its own (same origin);
//    4. Logout: POST /api/auth/logout—the server deletes the cookie.
//
// The form uses React 19’s ACTIONS: <form action={function}>.
// Instead of handling onSubmit and each field, we receive all the values
// from the form (FormData), and useActionState stores the result of the
// last action (in this case, an error message) and indicates whether it is in progress.
//
// A cookie belongs to a machine (localhost) and a path (/api): it
// is therefore common to TOUS all the examples. Once logged in here, examples
// 24 and 25 are as well.
// =========================================================================

import { useActionState, useEffect, useState } from 'react';
import { useFormStatus } from 'react-dom';

interface Utilisateur {
  login: string;
  nom: string;
  role: 'ADMIN' | 'DOCTOR' | 'USER';
}
interface Medecin {
  id: number;
  titre: string;
  prenom: string;
  nom: string;
}
interface Captcha {
  id: string;
  svg: string;
}
// the format of TOUTES the error messages in API
interface ErreurApi {
  statusCode: number;
  cle: string;
  params?: Record<string, string>;
}

// the few messages this example requires (example 25 will use i18next)
const MESSAGES: Record<string, string> = {
  'LOGIN.ERROR': 'Login ou mot de passe incorrect.',
  'ERRORS.WRONG_CAPTCHA': "Les caractères recopiés ne correspondent pas à l'image.",
  'ERRORS.TOO_MANY_ATTEMPTS': 'Trop de tentatives infructueuses. Réessayez plus tard.',
};

// a request GET, whose response JSON is typed; an error if it is not a 2xx
async function lire<T>(url: string): Promise<T> {
  const reponse = await fetch(url);
  if (!reponse.ok) {
    throw reponse; // we "trigger" the response itself: its status will indicate what to do
  }
  return (await reponse.json()) as T;
}

// the submit button: useFormStatus() determines whether the form QUI LE CONTIENT
// is being submitted (so it must be a separate component placed inside)
function BoutonConnexion() {
  const { pending } = useFormStatus();
  return <button className="btn btn-primary" disabled={pending}>{pending ? 'Connexion...' : 'Se connecter'}</button>;
}

// the result of the last login attempt
interface EtatConnexion {
  erreur: string | null;
  login: string; // the login entered, to display it again
}

export default function App() {
  const [utilisateur, setUtilisateur] = useState<Utilisateur | null>(null);
  const [medecins, setMedecins] = useState<Medecin[]>([]);
  const [captcha, setCaptcha] = useState<Captcha | null>(null);
  const [pret, setPret] = useState(false); // Has the initial verification been completed?
  const [erreurServeur, setErreurServeur] = useState<string | null>(null);

  async function chargerCaptcha() {
    setCaptcha(await lire<Captcha>('/api/captcha'));
  }

  async function chargerMedecins() {
    setMedecins(await lire<Medecin[]>('/api/medecins'));
  }

   // 1. Who is logged in? 200 -> the user; 401 -> no one
  useEffect(() => {
    async function verifierSession() {
      try {
        setUtilisateur(await lire<Utilisateur>('/api/auth/moi'));
        await chargerMedecins();
      } catch (e) {
        if (!(e instanceof Response) || e.status !== 401) {
          setErreurServeur('Le serveur JSON RdvMedecins est-il lancé (port 8080) ?');
        } else {
          await chargerCaptcha();
        }
      }
      setPret(true);
    }
    verifierSession();
  }, []);

   // 2. The connection: a ACTION, which receives the previous status and the
   // form data, and returns the new status
  async function seConnecter(_precedent: EtatConnexion, donnees: FormData): Promise<EtatConnexion> {
    const login = String(donnees.get('login'));
    const reponse = await fetch('/api/auth/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' }, // the body is JSON
      body: JSON.stringify({ login, password: donnees.get('password'), captchaId: captcha?.id, captcha: donnees.get('captcha') }),
    });
    if (!reponse.ok) {
       // the body JSON of the error response
      const erreur = (await reponse.json().catch(() => null)) as ErreurApi | null;
      const cle = erreur?.cle ?? 'ERRORS.SERVER_UNREACHABLE';
      await chargerCaptcha(); // Each image is used only once
      return { erreur: `${reponse.status} - ${MESSAGES[cle] ?? cle}`, login };
    }
    setUtilisateur((await reponse.json()) as Utilisateur);
    await chargerMedecins();
    return { erreur: null, login };
  }
  const [etat, actionConnexion] = useActionState(seConnecter, { erreur: null, login: 'admin' });

   // 4. Disconnection
  async function seDeconnecter() {
    await fetch('/api/auth/logout', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: '{}' });
    setUtilisateur(null);
    setMedecins([]);
    await chargerCaptcha();
  }

  let contenu;
  if (!pret) {
    contenu = <p className="text-muted">Vérification de la session...</p>;
  } else if (utilisateur) {
     // logged in
    contenu = (
      <div className="card p-3">
        <p>
          Connecté : <strong>{utilisateur.nom}</strong> ({utilisateur.login}), rôle{' '}
          <span className="badge text-bg-primary">{utilisateur.role}</span>
        </p>
        <h2 className="h6">GET /api/medecins</h2>
        <ul>
          {medecins.map((m) => <li key={m.id}>{m.titre} {m.prenom} {m.nom}</li>)}
        </ul>
        <p className="small text-muted">Rechargez la page (F5) : vous restez connecté.</p>
        <button className="btn btn-outline-secondary align-self-start" onClick={seDeconnecter}>Se déconnecter</button>
      </div>
    );
  } else if (!erreurServeur) {
     // not logged in: the form. The fields are not PAS validated: name
     // identifies them in FormData; after each action, React resets them to
     // their initial value (defaultValue)
    contenu = (
      <form className="card p-3" action={actionConnexion}>
        <div className="mb-2">
          <label className="form-label" htmlFor="login">Login</label>
          <input id="login" name="login" className="form-control" autoComplete="username" defaultValue={etat.login} />
        </div>
        <div className="mb-2">
          <label className="form-label" htmlFor="password">Mot de passe</label>
          <input id="password" name="password" type="password" className="form-control" autoComplete="current-password" />
        </div>
        <div className="mb-3">
          <label className="form-label" htmlFor="captcha">Recopiez les caractères de l'image</label>
          <div className="d-flex align-items-center gap-3 mb-2">
            <div dangerouslySetInnerHTML={{ __html: captcha?.svg ?? '' }} />
            <button type="button" className="btn btn-link btn-sm" onClick={chargerCaptcha}>Autre image</button>
          </div>
          <input id="captcha" name="captcha" className="form-control" autoComplete="off" />
        </div>
        <BoutonConnexion />
        <p className="small text-muted mt-2 mb-0">Comptes : admin, pelissier, martin... (mot de passe = login).</p>
        {etat.erreur && <div className="alert alert-danger mt-3 mb-0">{etat.erreur}</div>}
      </form>
    );
  }

  return (
    <div className="container py-4" style={{ maxWidth: 640 }}>
      <h1 className="h3 mb-3">Exemple 23 - connexion au serveur</h1>
      {contenu}
      {erreurServeur && <div className="alert alert-danger mt-3">{erreurServeur}</div>}
    </div>
  );
}

// All error responses from the RdvMedecins server have the same format:
//    { "statusCode": 409, "key": "ERRORS.LOGIN_TAKEN", "params": {...}, "fields": {...} }
// But a request can also fail (AUTREMENT): no response at all
// (network down: fetch sends a TypeError), or a response that doesn’t come
// from our server (a Vite proxy error page when the
// JSON server is down). We convert all of this to the UNE class,
// ErreurApi, which contains the translation key sent by the server (and,
// if any, its parameters, and the error for each field).
// =========================================================================

export class ErreurApi extends Error {
  readonly statusCode: number; // 0: the server did not respond
  readonly cle: string; // e.g., 'ERRORS.LOGIN_TAKEN'
  readonly params: Record<string, string>;
  readonly champs: Record<string, string>;

  constructor(statusCode: number, cle: string, params: Record<string, string> = {}, champs: Record<string, string> = {}) {
    super(cle);
    this.name = 'ErreurApi';
    this.statusCode = statusCode;
    this.cle = cle;
    this.params = params;
    this.champs = champs;
  }
}

// an error response (4xx, 5xx) -> a ErreurApi
export async function depuisReponse(reponse: Response): Promise<ErreurApi> {
   // the body of the error (JSON), if it exists and is in the correct format
  let corps: { cle?: string; params?: Record<string, string>; champs?: Record<string, string> } = {};
  try {
    const json: unknown = await reponse.json();
    if (typeof json === 'object' && json !== null) {
      corps = json;
    }
  } catch {
     // not JSON: our server did not respond
  }
   // no key: the proxy or network responded instead
  const cle = corps.cle ?? (reponse.status >= 500 ? 'ERRORS.SERVER_UNREACHABLE' : 'ERRORS.SERVER_ERROR');
  return new ErreurApi(reponse.status, cle, corps.params, corps.champs);
}
    • Lines 14–28: UNE class for all errors in API: the status HTTP (0: no response), the translation key sent by the server, its parameters, and the error for each field in a rejected form. It inherits from [Error]: it can be launched ([throw]) and recognized ([instanceof ErreurApi]). The “property parameters” of [TypeScript] ([constructor(public readonly cle: string)]) are not used: the [erasableSyntaxOnly] option of [tsconfig.json] disables them, because they generate code;
    • Lines 31–45: An error response becomes a [ErreurApi]. The body is not always from our server’s JSON: when the JSON server is down, the [Vite] proxy responds without a JSON body. No key: a status code of 500 or higher means “server unreachable.”

// common/api.ts - requests to API, on a single line
// -------------------------------------------------------------------------
// In Example 23, each request repeated the same steps: prefix
// /api, header JSON, test of response.ok, reading the error body... We
// group them here:

//    const doctors = await api.get<Person[]>('/doctors');
//    await api.post('/appointments', { day, idCreneau, idClient });
//
//    - if successful, the promise returns the body JSON, TYPÉ;
//    - if it fails, it is REJETÉE with a ErreurApi.

// where a problem such as COMMUN would be handled for all of them (see the case study and the
// 401 response). Used in Examples 24 and 25.

import { depuisReponse, ErreurApi } from './erreur-api';

export async function requete<T>(methode: string, url: string, corps?: unknown): Promise<T> {
  let reponse: Response;
  try {
    reponse = await fetch(`/api${url}`, {
      method: methode,
       // a body JSON (the server rejects a POST that is not a body)
      headers: corps === undefined ? {} : { 'Content-Type': 'application/json' },
      body: corps === undefined ? undefined : JSON.stringify(corps),
    });
  } catch {
     // fetch did not receive a AUCUNE response (network, server down)
    throw new ErreurApi(0, 'ERRORS.SERVER_UNREACHABLE');
  }
  if (!reponse.ok) {
    throw await depuisReponse(reponse);
  }
  return (await reponse.json()) as T;
}

export const api = {
  get: <T>(url: string) => requete<T>('GET', url),
   // A POST always has a JSON body: {} by default
  post: <T>(url: string, corps: unknown = {}) => requete<T>('POST', url, corps),
  put: <T>(url: string, corps: unknown) => requete<T>('PUT', url, corps),
  delete: <T>(url: string, corps?: unknown) => requete<T>('DELETE', url, corps),
};

    // =========================================================================
// 25-server-errors/src/App.tsx - display errors from SERVEUR
// -------------------------------------------------------------------------
// Customer management (admin account). This form does not
// VOLONTAIREMENT perform any validation in the browser: everything is sent
// to the server, which responds, in case of rejection, with an error JSON (converted
// to ErreurApi by commun/api.ts):
//
//    400 { key: 'ERRORS.INVALID_FORM', fields: { name: 'ERRORS.LASTNAME_REQUIRED' } }
//    409 { key: 'ERRORS.PATIENT_ALREADY_EXISTS', fields: { first_name: ..., last_name: ... } }
//    409 { key: 'ERRORS.CONCURRENT_UPDATE'         } (optimistic lock)
//
// The error in the CHAQUE field (ErreurApi.champs) is logged in the status and
// displayed below the field; its message is the CLÉ sent by the server,
// which the component translates (i18next). Editing a field clears its error.
// Try: an empty name, a title "Dr.", a namesake (Alice DURAND), a
// username already taken (martin), the same record edited in two tabs...
// =========================================================================

import { useState, useTransition, type FormEvent } from 'react';
import { useTranslation } from 'react-i18next';
import { api } from '../../commun/api';
import BarreConnexion from '../../commun/BarreConnexion';
import { ErreurApi } from '../../commun/erreur-api';
import type { Personne, Utilisateur } from '../../commun/types';
import { useConfirmation } from '../../16-confirmation/src/confirmation/confirmation';

interface SaisieClient {
  titre: string;
  prenom: string;
  nom: string;
  login: string;
  password: string;
  version: number;
}
type Champ = keyof SaisieClient;

const VIDE: SaisieClient = { titre: 'Mr', prenom: '', nom: '', login: '', password: '', version: 0 };

interface Message {
  cle: string;
  params?: Record<string, string>;
}

export default function App() {
  const { t, i18n } = useTranslation();
  const confirmer = useConfirmation();

  const [utilisateur, setUtilisateur] = useState<Utilisateur | null>(null);
  const [clients, setClients] = useState<Personne[]>([]);
  const estAdmin = utilisateur?.role === 'ADMIN';

   // the form: idEdite === null -> creation, otherwise modification
  const [idEdite, setIdEdite] = useState<number | null>(null);
  const [saisie, setSaisie] = useState<SaisieClient>(VIDE);
   // the error for each field (a translation error: CLÉ), returned by the server
  const [erreurs, setErreurs] = useState<Partial<Record<Champ, string>>>({});
   // the general message for the last error, and the success message
  const [erreurPage, setErreurPage] = useState<ErreurApi | null>(null);
  const [succes, setSucces] = useState<Message | null>(null);
   // useTransition: isPending is true during the execution of the action
   // is passed to startTransition—here, the data is sent to the server
  const [envoiEnCours, startTransition] = useTransition();

  async function recharger() {
    setClients(await api.get<Personne[]>('/clients'));
  }

  async function surConnexion(u: Utilisateur | null) {
    setUtilisateur(u);
    setClients([]);
    if (u?.role === 'ADMIN') {
      await recharger();
    }
  }

  function effacerMessages() {
    setErreurs({});
    setErreurPage(null);
    setSucces(null);
  }

  function nouveau() {
    setIdEdite(null);
    setSaisie(VIDE);
    effacerMessages();
  }

  function editer(c: Personne) {
    setIdEdite(c.id);
     // the VERSION read from the record is sent back with the modification: if someone
     // has modified the record in the meantime, the server will respond with a 409 error CONCURRENT_UPDATE
    setSaisie({ titre: c.titre, prenom: c.prenom, nom: c.nom, login: c.login ?? '', password: '', version: c.version });
    effacerMessages();
  }

   // a modified field: its value changes, its error disappears
  function modifier(champ: Champ, valeur: string) {
    setSaisie((s) => ({ ...s, [champ]: valeur }));
    setErreurs((e) => ({ ...e, [champ]: undefined }));
  }

  function enregistrer(evenement: FormEvent<HTMLFormElement>) {
    evenement.preventDefault();
    effacerMessages();
     // a transition ASYNCHRONE (React 19): envoiEnCours remains true until
     // the end of the function
    startTransition(async () => {
      try {
        const client =
          idEdite === null
            ? await api.post<Personne>('/clients', saisie)
            : await api.put<Personne>(`/clients/${idEdite}`, saisie);
        nouveau(); // form cleared, messages deleted...
         // ... except for this one
        setSucces({
          cle: idEdite === null ? 'FORM.AJOUTE' : 'FORM.MODIFIE',
          params: { nom: `${client.prenom} ${client.nom}`, login: client.login ?? '' },
        });
        await recharger();
      } catch (e) {
        if (!(e instanceof ErreurApi)) {
          throw e;
        }
        setErreurPage(e); // the general message
        setErreurs(e.champs); // the error for each field
      }
    });
  }

  async function supprimer(c: Personne) {
    const nom = `${c.prenom} ${c.nom}`;
    if (!(await confirmer(t('FORM.CONFIRMER_SUPPRESSION', { nom })))) {
      return;
    }
    effacerMessages();
    try {
      await api.delete(`/clients/${c.id}`);
      setSucces({ cle: 'FORM.SUPPRIME', params: { nom } });
    } catch (e) {
      setErreurPage(e instanceof ErreurApi ? e : null);
    }
    await recharger();
  }

   // an input field, with its error message translated
  function champ(nom: 'prenom' | 'nom' | 'login' | 'password', type = 'text') {
    const erreur = erreurs[nom];
    return (
      <>
        <label className="form-label" htmlFor={nom}>{t(`FORM.${nom.toUpperCase()}`)}</label>
        <input id={nom} type={type} className={`form-control ${erreur ? 'is-invalid' : ''}`} value={saisie[nom]}
               autoComplete={type === 'password' ? 'new-password' : 'off'} onChange={(e) => modifier(nom, e.target.value)} />
        {/* a server error message is a CLÉ: let’s translate it */}
        {erreur && <div className="invalid-feedback">{t(erreur)}</div>}
      </>
    );
  }

  return (
    <div className="container py-4">
      <div className="d-flex justify-content-between align-items-center mb-3">
        <h1 className="h3 mb-0">Exemple 25 - les erreurs renvoyées par le serveur</h1>
        <select className="form-select form-select-sm w-auto" value={i18n.language} onChange={(e) => i18n.changeLanguage(e.target.value)}>
          <option value="fr">FR</option>
          <option value="en">EN</option>
        </select>
      </div>
      <BarreConnexion onUtilisateurChange={surConnexion} />
      {utilisateur && !estAdmin && <p className="alert alert-warning">{t('FORM.ADMIN_SEULEMENT')}</p>}

      {estAdmin && (
        <div className="row g-4">
          <div className="col-lg-6">
            <table className="table table-sm align-middle">
              <tbody>
                {clients.map((c) => (
                  <tr key={c.id}>
                    <td>{c.titre} {c.prenom} {c.nom}</td>
                    <td><code>{c.login}</code></td>
                    <td className="text-end text-nowrap">
                      <button className="btn btn-sm btn-outline-primary me-1" onClick={() => editer(c)}>{t('FORM.MODIFIER')}</button>
                      <button className="btn btn-sm btn-outline-danger" onClick={() => supprimer(c)}>{t('FORM.SUPPRIMER')}</button>
                    </td>
                  </tr>
                ))}
              </tbody>
            </table>
          </div>

          <div className="col-lg-6">
            <form className="card p-3" noValidate onSubmit={enregistrer}>
              <h2 className="h5">{t(idEdite === null ? 'FORM.TITRE_AJOUT' : 'FORM.TITRE_MODIF')}</h2>
              <div className="mb-2">
                <label className="form-label" htmlFor="titre">{t('FORM.TITRE')}</label>
                {/* a "Dr" option that the server will reject: see ERRORS.INVALID_TITLE */}
                <select id="titre" className={`form-select ${erreurs.titre ? 'is-invalid' : ''}`} value={saisie.titre}
                        onChange={(e) => modifier('titre', e.target.value)}>
                  <option>Mr</option><option>Mme</option><option>Melle</option><option>Dr</option>
                </select>
                {erreurs.titre && <div className="invalid-feedback">{t(erreurs.titre)}</div>}
              </div>
              <div className="row g-2 mb-2">
                <div className="col-sm-6">{champ('prenom')}</div>
                <div className="col-sm-6">{champ('nom')}</div>
              </div>
              <div className="row g-2 mb-3">
                <div className="col-sm-6">{champ('login')}</div>
                <div className="col-sm-6">{champ('password', 'password')}</div>
              </div>
              <div className="d-flex gap-2">
                <button className="btn btn-primary" disabled={envoiEnCours}>{t('FORM.ENREGISTRER')}</button>
                <button type="button" className="btn btn-secondary" onClick={nouveau}>{t('FORM.ANNULER')}</button>
              </div>
              {succes && <div className="alert alert-success mt-3 mb-0">{t(succes.cle, succes.params)}</div>}
              {/* The general message and the status HTTP—to understand */}
              {erreurPage && (
                <div className="alert alert-danger mt-3 mb-0">
                  {t(erreurPage.cle, erreurPage.params)}{' '}
                  <span className="small text-muted">({erreurPage.statusCode} {erreurPage.cle})</span>
                </div>
              )}
            </form>
          </div>
        </div>
      )}
    </div>
  );
}
