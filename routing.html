    4. Routing

    4.1. Example 17: The router

    An application [React] is a single-page application: the browser loads only the UNE page HTML. When you click on an internal link, no request is sent to the server: the router changes the address displayed by the browser and replaces the displayed component. [React] does not have a router: the [React Router] library ([react-router] package), which is the most widely used, is used instead.

    [React Router] can be used in three ways (its “modes”): declarative (using the [<Routes>] and [<Route>] components, the simplest), “data” (routes described by objects, with functions executed before rendering: [loader], [middleware]...), and “framework” (a complete application with server-side rendering, similar to [Next.js]). We use the data mode, which provides the navigation controls we’ll need.

    // =========================================================================
// 17-router/src/routes.tsx - the ROUTES of the application
// -------------------------------------------------------------------------
// A React application is a single-page application (SPA: Single
// Page Application): the browser loads only UNE one page HTML. When you
// click an internal link, no request is sent to the server: the
// router changes the address displayed by the browser and replaces the
// component displayed in <Outlet />.
//
// React does not have a built-in router: the React Router library is used. A
// route associates a CHEMIN with a COMPOSANT (a "page"):
//    'doctors/:id'  :id is a parameter (/doctors/2 -> id = "2");
//    '*            ' any path: the "page not found" page (the
//                    router always chooses the most specific route).
// The routes are IMBRIQUÉES: the root route displays the shell of
// application shell (Shell), and its children are displayed inside it, at
// the location of its <Outlet />.
// =========================================================================

import { redirect, type RouteObject } from 'react-router';
import Coquille from './Coquille';
import Accueil from './pages/Accueil';
import ListeMedecins from './pages/ListeMedecins';
import DetailMedecin from './pages/DetailMedecin';
import Recherche from './pages/Recherche';
import PageIntrouvable from './pages/PageIntrouvable';

export const routes: RouteObject[] = [
  {
    path: '/',
    Component: Coquille,
    children: [
       // index: the route of the parent’s address itself (“/”)
      { index: true, Component: Accueil },
      { path: 'medecins', Component: ListeMedecins },
      { path: 'medecins/:id', Component: DetailMedecin },
      { path: 'recherche', Component: Recherche },
       // loading DIFFÉRÉ: the code for this page is only downloaded on the
       // first visit (Vite actually creates a separate file)
      { path: 'a-propos', lazy: async () => ({ Component: (await import('./pages/APropos')).default }) },
       // A redirect: the old URL leads to the new one. A LOADER
       // is a function that the router calls AVANT to display the route;
       // if it triggers a redirect, the navigation changes its target
      {
        path: 'docteurs',
        loader: () => {
          throw redirect('/medecins');
        },
      },
      { path: '*', Component: PageIntrouvable },
    ],
  },
];
    • Line 20: [RouteObject] is the type of a route; [redirect] creates a redirect;
    • lines 28–53: Routes are objects: a path ([path]) and a component ([Component], capitalized—we specify the component, not [<Accueil />]);
    • lines 30–32: Routes are nested: the root route displays the application’s “shell” ([Coquille]), and its children ([children]) are displayed at the INTÉRIEUR of the shell, at the location of its [<Outlet />]. The paths of the children are relative to that of the parent;
    • line 34: a route index: that of the parent’s address itself (“/”);
    • line 36: [:id] is a parameter: [/medecins/2] displays [DetailMedecin], where [id] = “2”;
    • line 40: deferred loading: the function [lazy] is called only on the first visit to the page. [import('./pages/APropos')] (a “dynamic” import, in the form of a function) then downloads the module, which [Vite] has stored in a separate file. [lazy] returns the missing properties of the route: in this case, its component, which is exported by default by the module;
    • lines 45–49: a redirect: the old address leads to the new one. A loader is a function that the router calls—AVANT—to display the route (to load its data); if it triggers ([throw]) a redirect, the navigation changes its target;
    • line 50: [*] corresponds to any path: the “page not found” page. The router always chooses the most specific route: the order of the routes does not matter.

    // =========================================================================
// 17-router/src/Coquille.tsx - the application’s “shell”
// -------------------------------------------------------------------------
//    - <Link to="...">, <NavLink to="...">: an internal link. It produces a
//      valid <a href>, but clicking it does not reload the page: this is the router
//      that handles it. NavLink also knows if it refers to the currently displayed page: it
//      then sets the "active" class (the Bootstrap class);
//    - <Outlet />: the location where the current route ENFANT is displayed;
//    - useLocation(): the current address (pathname, search...).
// =========================================================================

import { NavLink, Outlet, useLocation } from 'react-router';

export default function Coquille() {
  const location = useLocation();
   // decodeURIComponent: %C3%A9 becomes active again
  const adresse = decodeURIComponent(location.pathname + location.search);

  return (
    <div className="container py-4">
      <h1 className="h3 mb-3">Exemple 17 - le routeur</h1>
      <nav className="nav nav-pills mb-3">
        {/* end: "/" is only active on "/" exactly, not on /doctors */}
        <NavLink className="nav-link" to="/" end>Accueil</NavLink>
        <NavLink className="nav-link" to="/medecins">Médecins</NavLink>
        {/* Parameters after the "?": NavLink compares only the path */}
        <NavLink className="nav-link" to="/recherche?q=généraliste">Recherche</NavLink>
        <NavLink className="nav-link" to="/a-propos">À propos</NavLink>
        <NavLink className="nav-link" to="/docteurs">/docteurs (redirection)</NavLink>
        <NavLink className="nav-link" to="/page-inconnue">Lien cassé</NavLink>
      </nav>
      <p className="small text-muted">adresse courante : <code>{adresse}</code></p>
      <div className="card p-3">
        <Outlet />
      </div>
    </div>
  );
}
    • line 15: [useLocation()] returns the current address: [pathname] (the path), [search] (the part after the “?”)... The component is called each time the user navigates;
    • Line 24: [<NavLink to="...">] is an internal link. It generates a valid [<a href>] (which can be opened in a new tab), but clicking it does not reload the page: the router handles this. [NavLink] also knows if it refers to the currently displayed page: in that case, it adds the class [active] (the same as [Bootstrap]). [end]: The home page “/” is active only on “/” exactly, and not on [/medecins]; [<Link>] is the simple version, without an active class;
    • line 27: an address with parameters. [NavLink] compares only the path: the link remains active regardless of the search;
    • line 34: the location where the current route ENFANT is displayed.

    // =========================================================================
// 17-router/src/pages/DetailMedecin.tsx - a page with a parameter
// -------------------------------------------------------------------------
// useParams(): path parameters, here { id: "2" } - always
// CHAÎNES. useNavigate(): a function for navigating PAR LE CODE;
// navigate(-1) returns to the previous page, just like the Back button.
// If you navigate from /doctors/1 to /doctors/2, React RÉUTILISE uses the same
// component: it is simply re-rendered with a different ID.
// =========================================================================

import { useNavigate, useParams } from 'react-router';
import { MEDECINS } from '../donnees';

export default function DetailMedecin() {
  const { id } = useParams();
  const navigate = useNavigate();
  const medecin = MEDECINS.find((m) => m.id === Number(id));

  if (!medecin) {
    return <p className="text-danger mb-0">Le médecin n° {id} n'existe pas.</p>;
  }

  const suivant = (medecin.id % MEDECINS.length) + 1;
  return (
    <>
      <title>{`${medecin.prenom} ${medecin.nom}`}</title>
      <h2 className="h5">{medecin.titre} {medecin.prenom} {medecin.nom}</h2>
      <p>Spécialité : {medecin.specialite}</p>
      <div className="d-flex gap-2">
        <button className="btn btn-sm btn-outline-secondary" onClick={() => navigate(-1)}>Retour</button>
        <button className="btn btn-sm btn-outline-primary" onClick={() => navigate(`/medecins/${suivant}`)}>Médecin suivant</button>
      </div>
    </>
  );
}

    // =========================================================================
// 17-router/src/pages/Recherche.tsx - a page driven by the URL
// -------------------------------------------------------------------------
// /search?q=pediatrician: as with the GET form from the NestJS course, the
// page is fully described by its address: you can bookmark it
// bookmark, reload it, or go back. useSearchParams() provides the
// parameters after the ?.
// <Form> (from React Router) is a GET... form without reloading: the
// router navigates to /search?q=<input>. The page displays what
// the URL says, and nothing else.
// =========================================================================

import { Form, useSearchParams } from 'react-router';
import { MEDECINS } from '../donnees';

export default function Recherche() {
  const [parametres] = useSearchParams();
  const q = parametres.get('q') ?? ''; // is null if absent
  const resultats = MEDECINS.filter((m) => `${m.prenom} ${m.nom} ${m.specialite}`.toLowerCase().includes(q.toLowerCase()));

  return (
    <>
      <title>Recherche</title>
      <Form className="d-flex gap-2 mb-3" action="/recherche">
        {/* a validated NON field, which starts with the value of URL;
            key={q} : si l'URL change (bouton Précédent), React recrée le
            champ, qui reprend alors la nouvelle valeur de l'URL */}
        <input key={q} name="q" className="form-control" placeholder="nom ou spécialité" defaultValue={q} />
        <button className="btn btn-primary">Rechercher</button>
      </Form>
      <ul className="mb-0">
        {resultats.map((m) => (
          <li key={m.id}>{m.prenom} {m.nom} ({m.specialite})</li>
        ))}
        {resultats.length === 0 && <li className="text-muted">Aucun résultat.</li>}
      </ul>
    </>
  );
}
    • Line 17: the parameters after the “?”, in the form of an object [URLSearchParams]: [parametres.get('q')] is equal to [null] if [q] is absent. [useSearchParams] also returns (as the second element) a function to change them;
    • line 24: [<Form>] (from [React Router]) is a GET form... without reloading: upon submission, the router navigates to [/recherche?q=<saisie>] ([q] being the [name] for the field). As with the GET form from the [NestJS] course, the page is fully described by its address: you can bookmark it, reload it, or go back;
    • Line 28: The field is not validated; it starts with the value of the URL ([defaultValue]). If the URL changes without the page being reloaded (using the Back button), the field would retain its previous text; [key={q}] resolves this issue. When an element’s key changes, [React] treats it as a AUTRE element: it destroys the old one and creates a new one, which starts with the new default value. This is a common trick for “resetting” a component.

    // =========================================================================
// 18-guards/src/session.ts - a session SIMULÉE (without a server)
// -------------------------------------------------------------------------
// The logged-in user must be recognized by COMPOSANTS (the top bar,
// the calendar page) and by GARDES (the router’s functions, which are
// components and therefore cannot read a context). We store it
// in a simple, hand-coded module, a “store”:
//    - a private variable, the state;
//    - functions to read and modify it;
//    - `subscribe`: the list of functions to be notified when it changes.
// A component subscribes to it using useSyncExternalStore (see useSession): it
// is called when the state changes. Example 20 will delegate this task to a
// library, Zustand. (Example 23 will do the same thing with a real
// server.)
// =========================================================================

import { useSyncExternalStore } from 'react';

export type Role = 'ADMIN' | 'DOCTOR' | 'USER';

export interface Utilisateur {
  login: string;
  role: Role;
}

// three "hard-coded" accounts (password = login)
const COMPTES: Record<string, Role> = { admin: 'ADMIN', pelissier: 'DOCTOR', martin: 'USER' };

let utilisateur: Utilisateur | null = null; // the status
const abonnes = new Set<() => void>();

function changer(u: Utilisateur | null) {
  utilisateur = u;
  abonnes.forEach((prevenir) => prevenir());
}

export const session = {
  utilisateur: () => utilisateur,
  connecter(login: string, password: string): boolean {
    const role = Object.hasOwn(COMPTES, login) ? COMPTES[login] : undefined;
    if (role === undefined || password !== login) {
      return false;
    }
    changer({ login, role });
    return true;
  },
  deconnecter: () => changer(null),
  subscribe(prevenir: () => void) {
    abonnes.add(prevenir);
    return () => abonnes.delete(prevenir); // to unsubscribe
  },
};

// the component hook: the logged-in user, always up to date
export function useSession(): Utilisateur | null {
  return useSyncExternalStore(session.subscribe, session.utilisateur);
}

    The logged-in user must be known to the components (the top bar, the calendar page) and to the guards—router functions that are not components and therefore cannot read a context. It is stored in a simple, hand-written module, a store ([store]):

    • lines 29–30: the state, a private variable of the module, and the list of functions to notify when it changes;
    • lines 32–35: change the state and notify subscribers;
    • lines 37–52: the public functions: read the user, log in (three hard-coded accounts, password = login), log out, and subscribe ([subscribe] refers to the function that unsubscribes);
    • lines 55–57: the component hook. [useSyncExternalStore(subscribe, lire)] is the hook for [React] designed for this purpose: it subscribes the component to the store and calls it back when the read value changes.

    Example 20 will delegate this task to a library.

    // =========================================================================
// 18-guards/src/gardes.ts - navigation GARDES
// -------------------------------------------------------------------------
// A React Router MIDDLEWARE is a function called by the router
// AVANT to display a route that declares it (middleware: [...]), to CHAQUE
// navigation to it. It can:
//    - do nothing: navigation continues;
//    - throw a redirect, redirect('/address'): the
//      navigation is replaced by navigation to that address.
// It receives the navigation request (request.url: the requested address).
//
// This is the client-side equivalent of the NestJS (JwtAuthGuard,
// RolesGuard) — with one difference: FONDAMENTALE: a client key is
// merely a convenience. The client code is in the hands of the user, who
// can change it at will. True data protection remains that
// that provided by SERVEUR (see the chapter on the black box).
// =========================================================================

import { redirect, type MiddlewareFunction } from 'react-router';
import { session, type Role } from './session';

// the requested address, without the machine: "/agenda?x=1"
function adresse(request: Request): string {
  const url = new URL(request.url);
  return url.pathname + url.search;
}

// the page requires you to be logged in
export const connexionRequise: MiddlewareFunction = ({ request }) => {
  if (session.utilisateur() === null) {
     // not logged in: redirects to the login page, while remembering where you wanted to go
    throw redirect(`/connexion?redirect=${encodeURIComponent(adresse(request))}`);
  }
};

// the page requires one of the specified roles: a function that FABRIQUE retains it
export function roleRequis(...roles: Role[]): MiddlewareFunction {
  return ({ request }) => {
    const u = session.utilisateur();
    if (u === null || !roles.includes(u.role)) {
       // logged in, but not with the correct role: redirect to the home page, with an explanation
      throw redirect(`/?refus=${encodeURIComponent(adresse(request))}`);
    }
  };
}

    A middleware component [React Router] is a function that the router calls—AVANT—to display a route that declares it, and CHAQUE to navigate to it. It can do nothing (navigation continues), or trigger a redirection, which replaces the navigation.

    • Lines 23–26: It receives the navigation request: [request.url] is the full requested address ([http://localhost:5173/agenda?x=1]); only the path and parameters are retained;
    • lines 29–34: not logged in: redirects to the login page, while retaining the intended destination ([?redirect=...]);
    • lines 37–45: a function that returns FABRIQUE, a token, for the given roles; [...roles]: any number of arguments, grouped into an array. Logged in, but not with the correct role: redirect to the home page, with a reason.

    This is the client-side equivalent of the [NestJS] guards ([JwtAuthGuard], [RolesGuard]), with one difference: a client-side guard is merely a convenience. The client code is in the user’s hands, and the user can modify it at will. True data protection remains that provided by SERVEUR (see the chapter on the black box).

    // =========================================================================
// 18-guards/src/pages/Connexion.tsx
// -------------------------------------------------------------------------
// After logging in, the user is redirected to the page they wanted
// to open (with the ?redirect=... parameter set by the guard), or to the home page.
// =========================================================================

import { useState, type FormEvent } from 'react';
import { useNavigate, useSearchParams } from 'react-router';
import { session } from '../session';

export default function Connexion() {
  const redirection = useSearchParams()[0].get('redirect');
  const navigate = useNavigate();
  const [login, setLogin] = useState('');
  const [password, setPassword] = useState('');
  const [erreur, setErreur] = useState(false);

  function valider(e: FormEvent<HTMLFormElement>) {
    e.preventDefault();
    if (!session.connecter(login.trim(), password)) {
      setErreur(true);
      return;
    }
     // Only one path is accepted: INTERNE—it starts with /, but not with //
     // (//site.com/... refers to a AUTRE site) - no redirection to another site
    const interne = redirection !== null && redirection.startsWith('/') && !redirection.startsWith('//');
    navigate(interne ? redirection : '/');
  }

  return (
    <>
      {redirection && <p className="alert alert-warning">Connectez-vous pour ouvrir {redirection}.</p>}
      <form className="d-flex flex-wrap gap-2" onSubmit={valider}>
        <input className="form-control w-auto" placeholder="login" autoComplete="username" value={login}
               onChange={(e) => setLogin(e.target.value)} />
        <input type="password" className="form-control w-auto" placeholder="mot de passe" autoComplete="current-password"
               value={password} onChange={(e) => setPassword(e.target.value)} />
        <button className="btn btn-primary">Se connecter</button>
      </form>
      {erreur && <p className="text-danger mt-2 mb-0">Login ou mot de passe incorrect.</p>}
    </>
  );
}
    • Line 13: the address we wanted to open, handed over by the guard;
    • lines 27–28: after logging in, we go there... provided it is a INTERNE path (it starts with “/”, but not with “//”, which refers to another site): a booby-trapped login URL ([/connexion?redirect=https://site-malveillant.fr]) must not lead outside the application.
